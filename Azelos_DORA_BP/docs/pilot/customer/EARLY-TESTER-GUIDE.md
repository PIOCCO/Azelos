# ADORA — early tester guide (10–15 minutes to start)

Thank you for testing **ADORA** as an early design partner. This is a pre-production environment for **realistic DORA ICT third-party and resilience workflows**—not a compliance certification tool.

## 1. Access

- **URL:** (provided separately by Azelos)  
- **Login:** your email and password (provided via a **secure channel**, not public email if possible)  
- Use a modern browser (Chrome, Edge, Firefox, Safari)  
- If you received a **team invitation** instead, open the link you were given and set a password (minimum 12 characters)

## 2. First steps after login

1. Complete **policy acceptance** if prompted.  
2. Open **Get started** or **Organization profile** — set entity type/size (payment institution / EMI-style is fine).  
3. Review **Applicability** (which modules apply).  
4. Skim the **Dashboard** and **DORA overview**.

## 3. Data protection — important

Please **do not** upload confidential, personal, regulated, production, or customer data during this early test unless Azelos has agreed a separate data processing arrangement.

Use **synthetic or anonymized** examples only (fictional provider names, sample PDFs you create for testing).

## 4. Required test (main workflow)

**Story:** You are a European payment institution with several SaaS/cloud ICT providers. Understand dependencies, risks, controls, and evidence.

| Step | What to do |
|------|------------|
| Explore | Dashboard, Providers, Contracts, ICT Services, Business Functions, **Relationship map** |
| Create chain | New **Provider** → **Contract** → **ICT Service** |
| Dependencies | Link service to a **Business function** |
| Risk | Create or update an **ICT risk** assessment |
| Controls | Open **Controls**, update a status |
| Evidence | Upload a **synthetic PDF** on a provider/contract/control; try view/download |
| Map question | “If this provider fails, which functions are affected?” — use the **Relationship map** |
| Exports | Export **providers CSV**; generate **DORA assessment PDF** (Reports); ask Azelos for **tenant ZIP** steps if needed |

## 5. Optional exploration

Requirements, incidents, BCP/DR, resilience tests, findings, JSON reports, language (EN/FR).

## 6. Report bugs

Use the template Azelos sends ([`EXTERNAL-TESTER-BUG-REPORT.md`](../templates/EXTERNAL-TESTER-BUG-REPORT.md)) or email support with:

- What you were doing  
- Expected vs actual result  
- Screenshot (no confidential data)  
- Browser and approximate time  

## 7. Feedback

Complete the short questionnaire Azelos sends after 1–2 weeks of use. Honest “confusing / missing / useful” feedback is the goal.
